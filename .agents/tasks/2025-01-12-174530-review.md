# Customer-grouped sales view with payment modal

Transformed the shop page from a flat item list to a customer-centric view. Customers are now displayed as clickable cards showing aggregate data, and clicking a card opens a modal displaying that customer's name, all their items, and Payment & Credit buttons. The payment submission flow was expanded to support multi-bank transactions with transaction ID validation.

The `customer` field is extracted from uploaded Excel files via the `findValue` helper and included in each `UploadedItem`. Items are grouped by customer name in the UI, replacing the previous flat list. The payment request modal now requires transaction IDs for all bank entries and creates separate transaction records per bank, storing them in `confirmed_transactions` localStorage. The summary card, upload functionality, detail modal, and bottom navigation remain untouched.

**Watch for:** Payment modal state management complexity (likely), missing Credit button implementation (confirmed), Payment & Credit buttons in customer modal don't open separate modals (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The customer grouping logic is straightforward: reduce uploaded items by customer name, defaulting to "Unknown Customer" for items without a customer field. Customer cards display name, item count, total amount, and metadata badges. The customer modal mirrors this structure, listing all items for the selected customer in expandable detail cards.

Payment submission was rewritten to handle multi-bank payments. The main bank payment and additional bank payments are each stored as separate transaction objects with shared metadata (customer name, grand total, bank number, total banks). Transaction ID validation is enforced for all banks before submission.

The Credit button appears in the customer modal UI but has no click handler or modal implementation. The user requested "Payment & Credit buttons with full modal details from salesdashboard customer modal copy all features," but only the Payment button opens a functional modal. The Credit button is a visual placeholder.

Payment modal state grew from 2 fields (`paymentAmount`, `paymentNote`) to 7 (`paymentAmount`, `selectedBank`, `paymentReference`, `additionalPayment`, `additionalBanks`, `paymentNotes`, plus removed `paymentSuccess`). The modal now handles dynamic bank addition, per-bank transaction ID entry, and multi-transaction submission.

## Customer field extraction and grouping

The `findValue` helper searches for customer-related column names case-insensitively across a list of common variations: `'Customer', 'customer', 'CUSTOMER', 'Customer Name', 'CustomerName', 'customer name', 'CUSTOMER NAME', 'Client', 'client', 'CLIENT', 'Buyer', 'buyer', 'BUYER'`. If found, the value is trimmed and assigned to the `customer` field of the `UploadedItem` object:

```typescript
const customerValue = findValue([
  'Customer', 'customer', 'CUSTOMER', 'Customer Name', 'CustomerName',
  'customer name', 'CUSTOMER NAME', 'Client', 'client', 'CLIENT',
  'Buyer', 'buyer', 'BUYER'
])

// ...later in the returned object
customer: customerValue ? String(customerValue).trim() : undefined
```

Items are then grouped using a reduce that keys on `item.customer || 'Unknown Customer'`, producing a `Record<string, UploadedItem[]>` that is converted to a `CustomerGroup[]` array. Each group contains `customerName`, `items`, `totalAmount`, and `totalItems`. The flat item list is no longer rendered; customer cards are the only way to view uploaded items.

## Customer modal structure and button gaps

The customer modal is conditionally rendered when `showCustomerModal && selectedCustomer` is true. The modal backdrop closes the modal on click. The modal content shows: header (customer name, item count, close button), summary section (total amount, total items, total units), items list (expandable detail cards), and Payment & Credit buttons at the bottom.

**Confirmed issue**: The Credit button has `onClick={() => {}}`, an empty handler. The user requested "Payment & Credit buttons with full modal details from salesdashboard customer modal copy all features," but only the Payment button opens a functional modal.

**Likely issue**: When the Payment button is clicked from the customer modal, the payment amount is not pre-filled. The payment modal opens with an empty `paymentAmount` field. The global "Request Payment" buttons at the top of the page pre-fill with `totalAmount.toString()`, but the customer modal's Payment button does not pre-fill with `selectedCustomer.totalAmount`.

## Payment modal expansion

The payment request modal's state and submission flow were rewritten to support multi-bank payments. Removed `paymentNote` and `paymentSuccess`; added `selectedBank`, `paymentReference` (transaction ID), `additionalPayment`, `additionalBanks` (array of `{bank, amount, reason}`), and `paymentNotes`.

The modal now includes bank selector dropdown, transaction ID input (required), additional payment reason input, dynamic "Add Another Bank" section with per-bank amount and transaction ID, and notes field.

**Validation**: Before submission, checks that `paymentAmount` is a valid number > 0, `paymentReference.trim()` is non-empty, and every entry in `additionalBanks` has a non-empty `reason` field. If validation fails, an alert is shown and submission is aborted.

**Submission**: Each bank payment is stored as a separate transaction object in `confirmed_transactions` localStorage. The main bank and each additional bank get their own record with shared fields (`customerName`, `totalPaymentAmount`, `isMultiBankPayment`, `totalBanks`) and per-bank fields (`bank`, `amount`, `reason`, `bankNumber`).

**Confirmed issue**: The transaction records use `customerName: selectedCustomer?.customerName || 'Unknown'`, but the `Transaction` interface declares both `customer: string` and `customerName: string`. The `customer` field is never populated in the new submission flow.
