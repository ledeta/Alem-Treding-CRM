┌─────────────────────────────────────────────────────────┐

        ┌──────────┴──────────┐
        │                     │

        │                     │
        └──────────┬──────────┘
                   │
    ┌──────────────▼──────────────┐

        ┌──────────┼──────────┐
        │          │          │

    │Chat  │  │Notif.  │  │Dashboard│
    │Socket│  │Socket  │  │Socket   │
    └──────┘  └────────┘  └─────────┘

Message Flow (Example - Send Chat Message):
┌──────────────────────────────────────────────────┐
│  User types message & presses Enter              │
└────────────────────┬─────────────────────────────┘
                     │
        ┌────────────▼─────────────┐
        │  useChat.sendMessage()   │
        │  (socket emit)           │
        └────────────┬─────────────┘
                     │
        ┌────────────▼────────────────────┐
        │  Backend: send_message event    │
        │  • Validate message             │
        │  • Save to database             │
        │  • Create message object        │
        └────────────┬────────────────────┘
                     │
        ┌────────────▼───────────────┐
        │  Broadcast to room:        │
        │  io.to(room).emit(...)     │
        └────────────┬───────────────┘
                     │
        ┌────────────▼────────────────────────┐
        │  All clients receive:               │
        │  message_received event            │
        │  (updates local state)              │
        └────────────┬────────────────────────┘
                     │
        ┌────────────▼──────────────┐
        │  UI Auto-Updates          │
        │  • New message appears    │
        │  • Auto-scroll to bottom  │
        │  • Timestamp displayed    │
        └───────────────────────────┘

🔧 TECHNICAL SPECIFICATIONS
════════════════════════════════════════════════════════════════════════════════

Communication Protocol:
• Protocol: WebSocket (Socket.io)
• Transport: WebSocket with fallback to long-polling
• Encoding: JSON
• Compression: Enabled
• CORS: Configured for development

Performance Specifications:
• Message latency: <100ms
• Notification delivery: <50ms
• Dashboard update interval: 30 seconds
• Reconnection: Automatic (exponential backoff)
• Max reconnection attempts: 5
• Message history limit: 30 messages per conversation
• Unread count caching: Real-time
• Connection timeout: 60 seconds

Memory & Scalability:
• User connections mapped: HashMap (O(1) lookup)
• Conversation subscribers: HashMap (O(1) lookup)
• Message storage: 30-message circular buffer
• Notification queue: Unbounded (in production, add limits)
• Concurrent users per namespace: Unlimited (Node.js handles)

🔌 SOCKET.IO EVENTS REFERENCE
═════════════════════════════════════════════════════════════════════════════════

CHAT NAMESPACE (/chat)
──────────────────────

Client → Server (Emits):
  join_conversation       { conversationId: string }
  leave_conversation      { conversationId: string }
  send_message           { conversationId, message, messageType?, metadata? }
  edit_message           { messageId, conversationId, message }
  delete_message         { messageId, conversationId }
  mark_read              { messageId, conversationId }
  mark_conversation_read { conversationId }
  typing                 { conversationId, isTyping }
  get_active_users       { conversationId }
  direct_message         { recipientId, message }

Server → Client (Broadcasts):
  user_online            { userId, userName }
  user_offline           { userId }
  user_joined            { userId, userName }
  user_left              { userId, userName }
  user_typing            { userId, userName, isTyping }
  message_received       { id, conversationId, sender, message, ... }
  message_edited         { id, conversationId, message, editedAt }
  message_deleted        { id, conversationId }
  message_read           { id, conversationId, readBy }
  conversation_read      { conversationId, readBy, count }
  direct_message         { senderId, senderName, message, timestamp }
  error                  { message }

NOTIFICATIONS NAMESPACE (/notifications)
──────────────────────────────────────────

Client → Server (Emits):
  fetch_notifications    { page?, limit? }
  mark_read              { notificationId }
  mark_all_read          (no data)
  delete_notification    { notificationId }
  get_unread_count       (no data)
  get_statistics         (no data)
  ping                   { timestamp? }

Server → Client (Broadcasts):
  unread_count           { count }
  notification           { id, userId, type, title, message, ... }
  notification_read      { notificationId }
  all_notifications_read { markedCount }
  notification_deleted   { notificationId }
  notifications_fetched  { data[], unreadCount }
  statistics             { stats object }
  pong                   { data echoed back }
  error                  { message }

DASHBOARD NAMESPACE (/dashboard)
────────────────────────────────

Client → Server (Emits):
  get_dashboard_data     (no data)

Server → Client (Broadcasts):
  dashboard_update       { kpis, recentActivities, pendingRequests }
  kpi_update            { totalCustomers, totalSales, ... }
  activities_update     { activities[] }
  requests_update       { payments, credits, refunds }
  error                 { message }

🚨 ERROR HANDLING & RECOVERY
══════════════════════════════════════════════════════════════════════════════════

Connection Errors:
• ECONNREFUSED → Retry with exponential backoff
• ENOTFOUND → Check URL configuration
• Socket timeout → Reconnect automatically
• Network unreachable → Show offline indicator

Message Errors:
• Validation failed → Show user error
• Database error → Log and notify
• Permission denied → Show auth error
• Duplicate message → Ignore silently

Recovery Strategies:
• Auto-reconnect on disconnect
• Resend queue for failed messages
• Local state sync on reconnect
• Graceful UI degradation
• Fallback to HTTP polling if needed
